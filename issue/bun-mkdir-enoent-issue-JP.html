recursive mkdir の ENOENT

Windows の Bun で、"./" ・ ".\" ・ "sub/.." を recursive mkdir すると ENOENT になる。修正 PR の #42014 と #42635 では直らない

概要

2026-10-12 に oven-sh/bun#45059 として投稿した。

  • Windows で fs.mkdirSync(p, { recursive: true }) に ./ ・ .\ ・ sub/.. を渡すと、パスが空の ENOENT になる。3 つともカレント自身を指し、カレントは存在する。fs.promises.mkdir とコールバックの fs.mkdir も同じように失敗する
  • Node.js v26.11.1 と Deno 2.9.7 は、エラーにせずに返る
  • 修正 PR の #42014 と #42635 では直らない。#40536 は直す。2026-10-16 に出た #45410（Fixes #45059）も直す（.. で始まる EEXIST の件には手を付けていない）
  • 原因: os_path_kernel32 がこれらのパスを正規化して空の文字列にする。特別に扱うのは、ちょうど "." の入力だけ（エビデンス: ソース）
  • 直し方の候補: 正規化の結果が空なら "." にする（"." の特別扱いを、正規化の後ろへ移す）

再現コード: research/repro-enoent.cjs。同じケースは tests/mkdir-recursive.test.ts にもある。関連する EEXIST の不具合の詳細は 調査結果。

エビデンス: ソース

パスが空になる箇所

src/runtime/node/types.rs L1072-L1088（Bun 1.4.3、c6da4a4d3）。os_path_kernel32 の、相対パスを扱う部分:

            // Handle "." specially since normalizeStringBuf strips it to an empty string
            if s.len() == 1 && s[0] == b'.' {
                // SAFETY: see alignment note above (PathBuffer reinterpreted as [u16]).
                let buf_u16 = unsafe { bun_core::bytes_as_slice_mut::<u16>(&mut buf[..]) };
                return Ok(strings::to_kernel32_path(buf_u16, b"."));
            }
            let normal = bun_paths::resolve_path::normalize_string_buf::<
                true,
                bun_paths::platform::Windows,
                false,
            >(s, &mut b[..]);
            if !strings::fits_in_wide_path_buffer(normal) {
                return Err(NameTooLong);
            }
            // SAFETY: see alignment note above (PathBuffer reinterpreted as [u16]).
            let buf_u16 = unsafe { bun_core::bytes_as_slice_mut::<u16>(&mut buf[..]) };
            return Ok(strings::to_kernel32_path(buf_u16, normal));
  • コメントにあるとおり、normalize_string_buf は "." を空の文字列にする。そのため、正規化の前に "." だけを扱っている
  • ./ ・ .\ ・ sub/.. も正規化すると同じく空になるが、判定は 1 文字の "." にしか当たらない。空のパスのまま mkdir に渡り、ENOENT のメッセージのパスが空なのとも合う

各 PR で直る・直らない理由

PR変えているところENOENT の件
#42014NT に渡す名前の . ・ .. を、フォルダのハンドルを基準に解決する（src/sys/lib.rs の nt_object_name_at）❌ os_path_kernel32 は変えていない
#42635既にあるかの確認を、libuv の Win32 の stat（stat_w）に替える❌ os_path_kernel32 は変えていない
#40536src/runtime/node/node_fs.rs の recursive mkdir の入口で、相対パスをカレントと結合して（join_cwd_windows）から正規化する✅ 結合したパスは、正規化しても空にならず、カレントになる
#45410os_path_kernel32 そのものを変える。正規化した相対パスが空で、元の入力が空でないとき、getcwd で得たカレントを使う。ちょうど "." だけの特別扱いは外す✅ 空の文字列が kernel32 に渡らない。.. で始まる EEXIST の件は #42014 に任せている

#42635 の説明にも、その PR で child\.. の ENOENT は残り、#40536 が扱う、とある。#40536 は 1.4.1 を元にしていて、2026-08-26 から更新がない。
