このリポジトリの目的

  • Bun の不具合（Windows の fs.mkdir(path, { recursive: true })）を解決するためにある。調べて記録するだけでなく、直るところまで持っていくのが目的
  • 報告で最も重要なのは修正 PR でも直らないもの。直るものは短く済ませ、直らないものを先頭に書く

検証は指示を待たずに行う

共通ルールの「指示された範囲だけを実装する」「質問された時の対応」と違う運用にする。理由: 検証の結果が無いと、何を報告すべきか決められない。

  • 次の検証は、指示を待たずに行う。結果は報告する
    • 関連する issue ・ PR の検索、PR のソースの読み込み
    • 関連する PR の CI ビルド（Windows x64）を取得し、SHA-256 を照合して、テスト・再現コードを流す
    • 新しいケースを試し、見つけた失敗をテスト（tests/）と再現コード（research/repro.ts）に足す
  • 検証の結果が変わったら、同じ事実を載せた資料をすべて合わせる（調査結果・issue の資料・README の英語版と日本語版）。件数やケース名で全体を検索して漏れを探す
  • 外への書き込みは、従来どおり指示を待つ。issue ・ PR へのコメント、新しい issue、commit ・ push（commit ・ push は、次の項目の場合を除く）
  • Bun へ投稿したら、その回のうちに資料を更新し、commit ・ push まで行う。共通ルールの「重大な操作の確認方法」（commit と push は別の指示を待つ）と違う運用にする。理由: 投稿した事実と資料の記述がずれたままになるのを防ぐ
    • 対象: issue ・ PR へのコメント、新しい issue、投稿したものの編集
    • 更新する資料: 投稿の本文と URL、関連 issue ・ PR の一覧（日本語版と英語版の両方）。更新後は html2md ・ check-markdown ・ check-contrast を通し、push のあとは Pages の反映を確かめる
    • add するのは、その投稿に関わるファイルだけを名指しする
    • 投稿そのものは、従来どおり「投稿して」の指示を待つ
  • issue ・ PR ・ コメントの本文に書くリンクは、Markdown のリンク記法（[文字](URL)）にする。裸の URL は長く、本文が読みにくくなる。#42014 のような番号は GitHub が自動でリンクにするので、そのまま書く
  • PR のビルドと差分は _pr/<PR 番号>/ に置く（例: _pr/42014/）。bun-windows-x64.zip、展開した bun.exe、差分（pr.diff）など。_* で Git の管理から外れる。tmp/ と違い、使い終わっても消さない（再検証で使う）
  • ビルドを試した PR は、ソースも必ず読む。差分は gh pr diff <番号> -R oven-sh/bun で _pr/<番号>/pr.diff に保存して読む。差分だけで動きが分からないときは、Bun 本体の該当ファイルを _pr/base/<リビジョン>/ に取得して読む（リビジョンは bun --revision の値）。結果だけでなく、なぜ直る・直らないかをソースの箇所で示す

投稿した issue を定期的に確かめる

  • 対象: このプロジェクトから投稿した issue と、コメントした issue。いまは次の 2 つ。投稿が増えたら、ここに足す
    • oven-sh/bun#45059（投稿した issue）
    • oven-sh/bun#17332（コメントした issue。コメント 6118179563）
  • 時刻: 毎日 5:00 ・ 8:00 ・ 12:00 ・ 15:00 ・ 17:00 ・ 21:00（JST）。cron（0 5,8,12,15,17,21 * * *）で回す。セッションを開き直したときや、7 日で失効したときは、指示を待たずに作り直す。cron の指示文は「ローカルルールの 3 章に従い、投稿した issue を確かめる」の 1 行にし、手順を写さない
  • 手段: gh api で取る。取得と比較は tools/80_ops/issue-watch.ts で行う（node tools/80_ops/issue-watch.ts）
    • issue: repos/oven-sh/bun/issues/<番号>（状態 ・ ラベル ・ コメント数 ・ 更新日時）
    • コメント: repos/oven-sh/bun/issues/<番号>/comments（新しいコメント）
    • 自分のコメント: repos/oven-sh/bun/issues/comments/6118179563（リアクション）
    • 言及: repos/oven-sh/bun/issues/<番号>/timeline（ほかの issue ・ PR からの参照）
  • 見ること: 状態（open ・ closed）、ラベル、新しいコメント、自分のコメントへのリアクションと返信、関わる PR（#42014 ・ #42635 ・ #40536 ・ #45410）への言及
  • 前回との比較: 確かめた結果を etc/issue-watch.json に残し、次の回はそれと比べる
  • 報告するのは変化があったときだけ。変化がなければ何も言わない。返信や対応が要りそうなら、案を出して指示を待つ（外への書き込みは指示を待つ、は変えない）
